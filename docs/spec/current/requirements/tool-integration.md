# ツール・MCP 連携の要求

## 目的・対象範囲

既存の Copilot / VS Code の能力を利用し、必要な場合だけ専用ツールや MCP を追加する。エージェントの判断と、操作契約・権限の強制を分離する。対話で人の判断を得た後の状態の記録・遷移は、AI が管理下の経路を呼び出して行う。

状態: 要求定義ドラフト。

出典: [docs/idea/intial-idea.md](../../../idea/intial-idea.md) 第8・12章。共通要求: [common.md](common.md)。

## 機能要件・業務ルール

| ID | 大分類 | 機能 | 要求 |
| --- | --- | --- | --- |
| REQ-TOOL-001 | CAT-GUARD 操作制御 | FUN-TOOL-006 | ファイル検索・読み取り・編集、Git の確認、テスト・静的解析、必要なブラウザー検証を既存機能で利用できること。MCP は必須にせず、外部 GitHub 連携も任意とすること。 |
| REQ-TOOL-002 | CAT-GUARD 操作制御 | FUN-TOOL-002 | Git や外部サービスの書き込みは対象・操作を示して事前に許可を確認すること。push・PR・マージ等は対象操作ごとの許可を得ること。ファイル編集・検証は合意した案件・対象・操作の範囲内で反復でき、毎回同じ確認を要求しないこと。範囲変更時は再確認すること。ブラウザー検証はテスト環境に限定し、実サービスの購入・送信等を行わないこと。 |
| REQ-TOOL-003 | CAT-GUARD 操作制御 | FUN-TOOL-002 | 編集対象、検証に必要な読み取り先・生成先、外部操作先を分けて許可範囲を定めること。依存パッケージ・キャッシュ・一時ファイルへのアクセスは検証に必要な範囲で扱い、ワークスペース外であるだけで一律に拒否しないこと。許可範囲外のパス・symlink、ブランチ不一致、編集競合、未許可コマンドは拒否すること。dirty であるだけで既存変更を破棄しないこと。 |
| REQ-TOOL-004 | CAT-GUARD 操作制御 | FUN-TOOL-001 | 原本・状態・共同記録の管理下の更新で、変更 ID、対象ブランチ、期待リビジョンを照合すること。版の比較と書き込みを一体で行い、古い版の更新を拒否すること。再送され得る質問・決定の登録や状態遷移には操作 ID と適用結果を永続化して二重適用を防ぐこと。通常の文書の差分編集には操作 ID を一律に要求しないこと。構造化データを定義した形式で検証し、複数文書の途中更新を検出できること。管理下の書き込みは直列化し、手動編集も更新前に照合すること。手動編集との排他を保証したとは扱わず、同時編集が疑われる場合は更新を止めて調整すること。 |
| REQ-TOOL-005 | CAT-GUARD 操作制御 | FUN-TOOL-001 | 成功時に結果・変更内容・版・証跡参照を返し、失敗時に競合、権限不足、承認不足、阻害等の理由と再開方法を返すこと。状態不明の結果を成功と扱わないこと。 |
| REQ-TOOL-006 | CAT-GUARD 操作制御 | FUN-TOOL-003 | 承認の単位・版・記録は REQ-COM-003 と REQ-WF-006 に従い、回答者・役割・出所を残すこと。AI は人の回答を代理記録できるが、回答を創作したり任意の承認者名だけで承認したりしないこと。対話で得た回答の出所には、対話の識別情報と回答の要旨を用いること。 |
| REQ-TOOL-007 | CAT-GUARD 操作制御 | FUN-TOOL-004 | 操作中断・結果不明からの復旧では、保存された成果物と、登録操作等に用いた操作 ID を照合し、二重更新を防ぐこと。安全な状態を確定できなければ停止すること。専用 MCP が未導入でも必要な記録・前提チェックを既存機能で扱えること。MCP 固有の障害試験は検証対象外とする。 |
| REQ-TOOL-008 | CAT-GUARD 操作制御 | FUN-TOOL-005 | マージ前に原本・変更記録・実装・テストの整合と他案件による原本更新の影響を確認すること。許可された取り込みでは原本と実装を同じ変更として扱い、取り込み先コミットを記録すること。 |
| REQ-TOOL-009 | CAT-GUARD 操作制御 | FUN-TOOL-007 | AI による状態の記録・遷移は、期待版の照合・操作 ID・形式検証・復旧を備えた管理下の経路だけで行い、状態ファイルを直接編集しないこと。自動実行は、対象環境で未許可操作が拒否され、hooks 等の故障時にも拒否されることを人が確認した場合に限り有効にすること。この確認は導入時に workspace ごとに1回行い、人が実行する簡単な手順で有効化できること。確認前、確認できない場合、制御設定の変更後に再確認していない場合は自動実行を無効にし、記録を止めて確認手順を示すこと（手動利用は REQ-WF-016 の人の選択による）。有効化は人が判断し、AI が制御設定を変更したり有効化の手順を実行したりして自ら有効化しないこと。 |
| REQ-TOOL-010 | CAT-GUARD 操作制御 | FUN-TOOL-001 | 既存の文書・コードの管理下の更新は、全文の置き換えに加え、置き換える前後の文字列を指定する差分で行えること。差分の適用前に期待版を照合し、置き換える前の文字列が対象にちょうど1か所だけ存在しない場合は何も書き込まずに理由を返すこと。差分の更新にも、全文の更新と同じ許可・編集範囲・保護対象・記録・復旧を適用すること。AI は既存の文書・コードの部分的な変更に差分を使い、全文の置き換えは新規作成と全面改訂に限ること。 |
| REQ-TOOL-011 | CAT-GUARD 操作制御 | FUN-TOOL-001 | 指定したファイルの版だけを、内容を返さずに読み取れること。読み取り専用とし、保護対象・workspace 外のパスは拒否すること。 |

### 必要な操作能力

以下は操作契約の候補であり、同名の MCP ツールの存在や専用サーバーの実装を要求するものではない。既存機能または採用した専用ツールで能力と制約を満たす。

| 操作候補 | 必要な能力・制約 |
| --- | --- |
| `change.register` | 変更 ID・ブランチ・基点を登録。ブランチを作成したことにはしない |
| `scratchpad.read` | 内容と版を読み取る。副作用なし |
| `revision.read` | 指定ファイルの版だけを返す。内容は返さない。副作用なし |
| `document.update` | 期待版を確認し、差分（置き換える前後の文字列）または全文で更新して新版を返す |
| `scratchpad.update` | 期待版を確認して差分更新し、新版を返す。再送され得る登録操作は操作 ID も確認する |
| `question.open` | 質問と影響作業を記録し、質問 ID を返す |
| `question.record_answer` | 対話で確認した人の回答と出所を記録。承認・仕様反映を自動的に完了としない |
| `decision.record` | 根拠・質問・正式成果物参照付きで決定を残す |
| `approval.request` | 対象工程の成果物一式の版と必要な役割を対話で示して人へ承認を依頼。自分では承認しない |
| `workflow.transition` | 質問・成果物・許可・承認の前提を検証して状態を更新。前提を満たした時点で AI が呼び出し、人に実行を求めない |
| `traceability.validate` | 参照切れ・未対応等を検出。意味上のレビューの代わりにしない |

## 非機能要件

| ID | 要求 |
| --- | --- |
| NFR-TOOL-001 | 本仕組みが利用する経路では、未許可の外部書き込み・本番操作、REQ-TOOL-003 の許可範囲外のファイル操作、読み取り専用担当による書き込みをホスト・ツール側で拒否できること。拒否できない操作はその自動実行経路を無効にし、人の操作を案内すること。状態の記録・遷移の経路を無効にした場合は記録を止め、確認手順と、人が選べる手動利用を示すこと（REQ-WF-016）。警告だけで利用可能にせず、制御できない操作に限って手動とし、許可された編集・検証まで一律に停止しないこと。工程の進行や対話は手順で制御し、すべての会話や一般コマンドへの一律の hooks は要求しない。 |
| NFR-TOOL-002 | 操作先、結果、証跡を確認でき、秘密情報をマスクすること。状態を可能な限り Git 管理の成果物から復元でき、隠れたサーバー状態だけを唯一の根拠にしないこと。 |

## 受入条件

| ID | 対象 | 条件・期待結果 |
| --- | --- | --- |
| AC-TOOL-001 | REQ-TOOL-001、REQ-TOOL-007 | 専用 MCP と GitHub 連携が未導入でもローカル成果物の読み取り・記録・前提確認を行える。対象内で利用できない検証は不足として表示する。MCP 連携試験はこの条件に含めない。 |
| AC-TOOL-002 | REQ-TOOL-002、NFR-TOOL-001 | 未許可の push・外部書き込み・本番操作を試みても実行されない。拒否できない経路は無効となり、自動操作ではなく人による操作を案内する。警告を表示するだけではこの条件を満たさない。 |
| AC-TOOL-003 | REQ-TOOL-003 | 許可範囲外のパス・symlink、別ブランチ、未許可コマンドを指定すると拒否され、既存ファイルとユーザー変更が残る。許可した依存パッケージの読み取りやキャッシュ・一時ファイルへの生成は、検証で利用できる。 |
| AC-TOOL-004 | REQ-TOOL-004、REQ-TOOL-005 | 管理下の更新後に古い版から次の更新を試みると、競合理由を返し、先の変更を失わない。不正形式は変更前に拒否される。手動編集との競合を検知した場合も上書きせず停止する。通常の差分編集に操作 ID がないことだけで更新を止めない。 |
| AC-TOOL-005 | REQ-TOOL-006 | 人の回答がない状態では承認者名だけで承認済みにしない。対象版への対話での明示的回答があれば、追加の本人認証なしで回答者・役割・出所（対話の識別情報と回答の要旨）を代理記録できる。 |
| AC-TOOL-006 | REQ-TOOL-007、NFR-TOOL-002 | 更新結果不明の障害を再現すると、保存結果の照合前に再更新せず、復旧または停止を提示する。再起動後も Git 管理の記録から状態と残作業を確認できる。 |
| AC-TOOL-007 | REQ-TOOL-008 | 他案件の原本更新や今回の原本反映漏れがあるとマージ準備を止める。整合・再検証・必要な承認と操作許可が揃った場合のみ取り込み、コミットを記録する。 |
| AC-TOOL-008 | NFR-TOOL-002 | ダミーの秘密情報を含む操作結果を記録しても、文書・Scratchpad・ログから実値を取得できない。 |
| AC-TOOL-009 | REQ-TOOL-004、REQ-TOOL-005 | 同じ操作 ID を再起動後に再送しても質問・決定が二重登録されず、適用済みの結果を確認できる。原本と変更記録の一方だけを更新して中断すると、未完了の更新を検出し、整合が回復するまで工程移行を止める。 |
| AC-TOOL-010 | REQ-TOOL-002 | 同じ許可範囲内のファイル編集・テスト実行は、反復ごとに再確認を要求しない。操作先や範囲が変わる場合と push・PR・マージでは必要な許可を確認する。 |
| AC-TOOL-011 | REQ-TOOL-009 | 導入直後の構成では、AI は管理下の経路を自動実行せず、確認待ちと有効化の手順を表示する。人が確認後に有効化の手順を1回実行すると、AI が管理下の経路を呼び出して記録し、組み込み編集による状態ファイルの直接更新は拒否される。AI が制御設定を変更したり有効化の手順を実行したりして自動実行を有効にしようとすると拒否される。 |
| AC-TOOL-012 | REQ-TOOL-010 | 既存の文書の1行を差分で直すと、その行だけが変わり新しい版が返る。置き換える前の文字列が0か所または2か所以上ある、または期待版が古い場合は、ファイルを変えずに理由を返す。許可のない差分、状態ファイルへの差分は全文の更新と同じく拒否される。 |
| AC-TOOL-013 | REQ-TOOL-011 | 版の読み取りで、指定ファイルの版（未作成は空）だけが返り、内容は返らない。制御設定・秘密ファイル・workspace 外のパスは拒否される。 |
