# 共通要求

## 目的・対象範囲

GitHub Copilot / VS Code 上で、アイデア出しから要件定義、外部・内部設計、開発・テストまでを支援する AI エージェント、スキル、ツールの要求を定義する。他のプロジェクトにも導入できる形で配布し、新規プロジェクトを主な対象とする。導入後の追加・修正も扱い、既存システムへ導入する場合は既存構成への適用範囲を確認する。

状態: 要求定義ドラフト。作成依頼を要件承認とは扱わない。

出典: [docs/idea/intial-idea.md](../../../idea/intial-idea.md) 第1〜3・6〜11章。参照日: 2026-10-13。

本要求の対象は開発支援の仕組みであり、アイデア文書に登場する注文管理等のアプリを作る要求ではない。設定ファイル数、状態の保存形式、対応バージョン、具体的なツール名、モデル、専用 MCP の採否は要求で固定せず設計で具体化する。数値の性能目標等を根拠なく補わない。

## 用語と記述ルール

文書一覧と読む順序は [README.md](README.md) を参照する。

- ユーザー: Copilot を操作する人。発注者・技術責任者と同一とは限らない。
- 発注者: アイデア、要件、外部設計を承認する役割。
- 技術責任者: 内部設計、開発完了を承認する役割。
- エージェント: 担当する役割。スキル: 再利用する手順。ツール: 具体的な操作能力。
- 現行原本: 既定ブランチの全体仕様。原本候補: 変更ブランチ内の次版。
- リビジョン: 対象の版を特定し、変更を検知できる識別情報。具体方式は設計で決定する。

要求 ID は `REQ-<領域>-番号`、非機能要件 ID は `NFR-<領域>-番号`、受入条件 ID は `AC-<領域>-番号`、機能 ID は `FUN-<領域>-番号`、大分類 ID は `CAT-<英字略称>` とし、表には略称と日本語名を併記して（例: `CAT-FLOW 工程進行`）、日本語名は README の索引で定義し、全体で一意にする。各要求は機能要件の表で大分類と機能を示す。大分類は [README.md](README.md) の機能一覧で定義し、機能は各文書の「提供する機能」で定義する。要求の大分類は、その要求が対応する先頭の機能の大分類とする。ファイル移動だけで ID を変更しない。各機能文書は共通要求を参照し、本文を複製しない。要求間の矛盾は質問して解消する。

## 非機能要件

| ID | 要求 |
| --- | --- |
| NFR-COM-001 | 共通の役割・手順・操作契約と、Copilot 固有の登録・呼び出しを分離できること。他環境への移植可能性を保つが、初期の動作確認対象は Copilot / VS Code とすること。 |
| NFR-COM-002 | 秘密情報、不要な個人情報、AI の非公開の思考過程を文書・Scratchpad・ログへ保存しないこと。記録は判断の根拠、質問、決定、観測結果に限定すること。 |
| NFR-COM-003 | 外部資料、Issue、コード等の取得内容を非信頼データとして扱い、そこにある命令から操作権限や承認を得たと判断しないこと。 |
| NFR-COM-004 | 役割に応じた最小権限を用い、ユーザーの既存変更を保護すること。未検証と権限制御の制約を隠さないこと。 |
| NFR-COM-005 | 設計で対応バージョン・利用に必要な機能・権限を明示すること。対象環境で利用可否を確認でき、必要な機能がなければ不足と代替可否を提示すること。 |
| NFR-COM-006 | 検証用スクリプト・hooks は、原本・状態の整合性や必要な操作制限を既存機能だけで満たせない場合に限定すること。追加理由、対象操作、利用手順を示し、通常の対話・読み取りや合意範囲内の反復作業へ不要な停止・再確認を加えないこと。 |
| NFR-COM-007 | 人が実行・確認するコマンドと操作について、使う場面、入力の各項目の意味と値の取り方、結果とエラーの読み方、実行前に確かめることを、人が読める参照資料で確認できること。参照資料は形式定義と矛盾せず、すべての操作を含むこと。利用者向けと導入・管理者向けの手順は、それぞれの人が行う作業の順に示し、通常の利用者に参照資料の読解を求めないこと。 |

## 対象外・設計で具体化する事項

対象外は、AI による人間の承認判断の代行、無許可の本番操作、特定アプリの業務仕様の固定、承認の本人認証・改ざん防止基盤である。役割の並行実行と MCP 連携は検証対象外とし、その検証を完了の必須条件にしない。対象外の機能を検証済みと表示しない。この除外は、支援先アプリの開発・テストを省略する意味ではない。人の承認回答の代理記録は許容する。専用 UI・専用 MCP サーバーは必須にせず、必要な補助機能は NFR-COM-006 の範囲に限定する。

設計では、簡単な導入・更新方法、設定ファイル数、Copilot の設定・対応バージョン、状態・リビジョンの形式、具体的なツール名、必要な権限制御と補助機能、承認回答の記録方法、対話による自動記録の有効化条件と手順、手動利用の選び方、MCP の採否を決める。要求を満たせない制約が判明した場合は、人に選択肢と影響を提示し、要求を独断で弱めない。
