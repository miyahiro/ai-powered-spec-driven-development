# 要求定義の変更（CHG-0002）

状態: 要求定義ドラフト（案。工程承認済みではない）。アイデア（[idea.md](idea.md)）も工程承認前であり、本書の作成を承認とは扱わない。
入力・出所: [idea.md](idea.md)、宮下さんの依頼（2026-10-20「状態管理の仕組みは実現したまま、状態遷移を人がコマンドを実行して進める方式から AI との対話で自動的に遷移させる方式へ改める」）と同日の確認回答、基点の要求定義書（コミット `4146b36` の [docs/spec/current/requirements/](../../current/requirements/README.md)）。

## 変更の要旨

状態遷移の方式を、人が request を作りランナーのコマンドを実行する手動標準から、人は対話で判断を答え、AI が回答を確認して管理下の経路（既存ランナー）で記録・遷移させる Human-in-the-loop の方式へ改める。状態の形式、期待版の照合、操作 ID、復旧、承認の単位・役割は変更しない。

## 理由

- 手動標準では、AI が request を作り人が実行する往復が発生し、読み取り範囲の誤り等の手戻りが出た（[idea.md](idea.md) の現行の観察）。
- 人の判断は対話に集約し、書き込みは既存ランナーを通すことで、期待版・操作 ID・復旧の仕組みを失わずに手間を減らせる（idea.md の候補 1。人の選択と一致）。

## 影響

- 互換性: 状態ファイルの形式とランナーの操作契約は変えない。手動利用は代替手段として残るため、既存の手動手順も使える。
- 再承認: CHG-0002 の工程承認はまだないため、取り直す承認はない。アイデア工程から順に承認を受ける必要がある。
- 後工程: 外部・内部設計を本変更で合わせて更新した（[external-design.md](external-design.md)、[internal-design.md](internal-design.md)）。`.github/` 配下の agent・skill・ランナー利用方法・ユーザーガイドは、宮下さんの依頼（2026-10-20）により本変更で更新した（[internal-design.md](internal-design.md) の影響）。
- 状態記録: 本書と原本の更新は人の依頼による直接編集であり、ランナー経由の記録（`state.json`）は更新していない。CHG-0002 の状態は ideation のドラフトのまま。
